# Blue/teal storefront implementation plan

**Goal:** Integrate the supplied September 15 blue/teal demo into the current production storefront and ship verified production behavior.

**Architecture:** Retain static HTML, native ES modules, the detailed four-service builder, Neon, and private Blob storage. Adopt the demo homepage and project dialogs. Replace its local demo inbox with a separate minimal inquiry API; unknown intent must never become paid consulting. No framework migration.

**Design/spec:** The supplied ZIP's `BLUE-TEAL-REVISION.md` defines the visual target. `INTEGRATION-NOTES.md` defines the boundary between prototype and production. This plan records the reviewed production interpretation: integrate the actual demo features, not its entire future growth roadmap.

## Comparison and decisions

- Adopt canvas #F3F6FA / #101923, surfaces #FFFFFF / #182532, blue action #245ADB / #8FB8FF, teal #0B7878 / #65D8CF. Keep system/light/dark themes consistent across routes.
- Adopt outcome-led hero, outcome cards, filterable project examples, detail/share dialogs, maker/process/business sections, and short inquiry. Use current local owner-approved photos and retain the full original-design portfolio.
- Keep the current detailed builder as a real navigable route rather than the demo iframe, which conflicts with production frame protections.
- Remove demo ribbon, inbox, fake API, noindex, remote image probing and prototype success claims. Retain canonical SEO and structured data.
- Add a separate quick inquiry contract accepting email plus description, HTTP(S) URL, or attachments; optional name and explicit neutral intent. No estimate, shipping address, payment, or detailed-service coercion.
- Use a separate Neon table and private Blob paths for inquiries. Use a high-entropy submission key for idempotency and ownership, validate all fields server-side, check completed uploads, bound attachment count/size, and add abuse controls. Database acceptance and notification state remain distinct. Unconfigured/API-failure mode must retain email/download recovery.
- Keep existing prices. Independently verify the demo's blank slicer input and minimum-range fixes against the current engine.
- Keep browser CSP restrictive; add only the actual private Blob upload connection destination and blob image previews if needed.
