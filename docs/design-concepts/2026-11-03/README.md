# Partner / administration workspace directions

Open `index.html` in a browser. All assets are local; no build, API, network request, account or private data is required. Records are fictional. This is a task interaction study, not a replacement application.

## Shared requirements

- Blue/teal brand, flat surfaces, restrained borders, system Segoe UI typography, no gradients or decorative charts.
- One clear current task with explicit next action. Supporting terms, payment distinctions and consent remain near the decision.
- Full partner and administration navigation grouped by work, records and account/program controls. A native Workspace menu exposes all destinations on mobile; nothing relies on a clipped horizontal strip.
- Semantic headings, native controls and disclosure, visible focus, 44px control targets, light/dark/system appearance, no motion or remote dependencies.
- Owner review comes first. Consequential program/account/finance destinations remain grouped separately, rather than mixed into a single long form.

## The array

**A — Fluent task workspace.** Stable side navigation, a central task sheet and compact context column. Best overall balance: familiar administrative orientation with an obvious partner next step. Suggested basis for implementation, with focused mobile disclosure.

**B — Material workbench.** Top-level workspace menu, more distinct task surfaces, prominent progress, rounder action treatment and queue/detail composition. Suits repeated owner triage; occupies more vertical space on mobile.

**C — iOS / Metro task flow.** Narrow working surface, stronger task title, full-width primary action and sequential context. Suits occasional phone-based partner visits; comparison of owner records is slower than A/B.

The concepts intentionally share content and tokens so votes assess information hierarchy and working flow rather than brand preference. Their navigation, density, surface structure, context placement and action arrangement differ.

## Evidence

`node --check concepts.js` passed. Playwright opened all three directions in both roles at 1440×810 and 390×520, asserted no document horizontal overflow, exercised the visit-proof form and theme selector, and captured 13 workspace images. Desktop A and mobile A owner captures were visually inspected. These checks validate the prototype only; production integration and full application regression coverage remain outstanding.

HTML generated by the prototype script uses authored constant content; user-entered review notes are never inserted into HTML. The prototype does not persist, submit, send, approve or pay anything. Out-of-sample destinations explain their limited scope rather than pretending to navigate.
